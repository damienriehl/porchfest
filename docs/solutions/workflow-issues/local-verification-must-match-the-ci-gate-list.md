# Local green is only meaningful against the same gate list CI runs

## Context

The U3 branch was verified locally with `typecheck`, `lint`, the full test suite (155/155),
and the container smoke test — all green, twice over, by two workers and the orchestrator.
CI failed in 20 seconds.

## What was missed

`.github/workflows/ci.yml` runs **seven** steps. Local verification habitually ran four of
them. The missing one that failed was `npm run format:check` (`prettier --check .`). Nobody
had ever run it: not the workers, whose reports each listed typecheck/lint/test, and not the
orchestrator, who inherited that same list from the reports.

A gate that exists in CI but is absent from everyone's local habit is invisible until it
fires, and it fires at the least convenient moment — after the push, on a public PR.

## The underlying defect it exposed

The failure was not merely "someone forgot to run prettier." There was **no
`.prettierignore` in the repository at all**, so `prettier --check .` policed generated
output alongside authored source:

- `packages/core/drizzle/` is written by drizzle-kit. Reformatting it means fighting the
  generator on the next migration.
- `docs/plans/` holds artifacts imported verbatim from another repository, where
  byte-identity with the source is the point.

Three of the fifteen failures pre-dated the branch entirely, on files in `packages/map/` —
meaning CI had been red on `main` too, and nobody had noticed.

## The fix

Add a `.prettierignore` covering generated and imported trees, then format the rest. Do not
"fix" a generated file by reformatting it; exclude it, and say why in the file:

```
# Generated by drizzle-kit — reformatting these fights the generator.
packages/core/drizzle/

# Imported canonical artifacts, kept verbatim so they stay diffable against
# their source of record.
docs/plans/
```

## The habit to keep

Before pushing, read `.github/workflows/ci.yml` and run **every** step it runs, in order —
not the subset you remember. When a worker reports its gates, check that list against CI's
rather than adopting it. A worker's verification table is evidence of what it ran, never
evidence that what it ran was sufficient.
