## Two environment traps that will cost you an hour each

**Use Node 24.** `engines`, both CI jobs, and the Dockerfile pin it, but nvm's
default on this box is not it. On the wrong Node, `better-sqlite3` fails to load
and **the entire suite fails across files nobody touched** — it reads exactly
like a catastrophic regression. Check `node --version` before believing a mass
failure. The fix is `nvm use 24`; `npm rebuild` under the wrong Node makes it
worse for everyone else sharing the checkout. This happened four times in one
day, twice caused by review subagents rebuilding mid-run.

**Another agent works in this repo.** Commits appear on working branches
mid-session. Damien's ruling: let them do their work, do yours, and merge only
your own. It surfaces as the cross-model controller refusing `integrate`
("canonical HEAD advanced outside the recorded wave") or `prepare` ("canonical
branch changed") — that situation, not a bug. **Do not run a code review
concurrently with a worker**: they share `node_modules`, and a review's rebuild
breaks the worker's gate.

`PR #19` is that agent's, implementing the same read-only feature #21 shipped. It
is not yours to resolve.

## Constraints a later PR must not undo

Everything in `docs/handoffs/2026-08-24-u5-merged-and-archival-closed.md` still
holds — KTD7 everywhere, a house-level coordinate _is_ a home address,
`email_log` survives anonymization, the sweep must never break boot, the core
test-support seam is test-only. Added since:

- **The archived wording in `lifecycleRefusal` is byte-identical on purpose**,
  and its non-archived branches are deliberately unreachable defensive code with
  tests that say so. Do not "fix" them into route tests or delete them as dead.
- **An unknown record id must keep answering 404** — `findItem` runs before the
  lifecycle branch.
- **The recovery CLI adds no HTTP surface and needs no core function.** Its link
  expires in an hour, not the seven-day invite default, and it must keep failing
  loudly when `PORCHFEST_DATA_DIR` is wrong rather than creating an empty
  database.
- **The public sign-in page must not name a repo path** or advertise the shell
  recovery procedure.
